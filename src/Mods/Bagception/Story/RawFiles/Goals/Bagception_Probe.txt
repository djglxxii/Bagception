// Bagception, Phase 1.
//
// This goal now does two unrelated jobs, kept apart below:
//
//   SHIPPING     one Bagception per character, with its internal containers,
//                granted and repaired idempotently.
//   DIAGNOSTICS  the Phase 1 probe. Its questions are answered and recorded in
//                docs/tracking/decision-log.md; these rules exist only until the
//                sorter is written, and must not ship.
//
// DB_Bagception_GrantPending is declared here only to give the database a defined
// shape; the NULL entry never matches a real character.
//
// GUIDSTRING, not CHARACTER. The grant rules bind a CHARACTER, but the rule that
// clears the flag takes its holder from TemplateAddedTo, whose _InventoryHolder is a
// GUIDSTRING. GUIDSTRING accepts a CHARACTER; the reverse is a type error.
DB_Bagception_GrantPending((GUIDSTRING)NULL_00000000-0000-0000-0000-000000000000);

// INITSECTION no longer carries the grant flag. The grant used to hang off a DB flag asserted
// here, which was consumed once and could never recover if the grant was missed.
// The inventory-count guard below replaces it and is self-healing.

KBSECTION

// ---------------------------------------------------------------------------
// SHIPPING: one Bagception per character
// ---------------------------------------------------------------------------
//
// Follows the vanilla pattern for the camp supply pack in Gustav's _Gustav_Init:
// react to CharacterJoinedParty, and guard with TemplateIsInInventory(..., 0) so a
// character who already has one is skipped. Vanilla adds QRY_OnlyOnce because the
// pack is one per party; Bagception is one per character, so that guard is dropped
// and the inventory check does the work instead.
//
// The inventory check is what makes these rules idempotent and self-healing: they
// can fire as often as they like and a character ends up with exactly one bag. That
// is a better guard than the DB flag used earlier, which was consumed once and
// could never recover if the grant was missed.

// New arrivals: recruits, hirelings, anyone joining later.
IF
CharacterJoinedParty(_Character)
AND
TemplateIsInInventory((ITEMROOT)BAGCEPTION_CONT_Master_856bd140-6963-4de1-9471-25440149e87d, _Character, 0)
AND
NOT DB_Bagception_GrantPending(_Character)
THEN
DB_Bagception_GrantPending(_Character);
TemplateAddTo((ITEMROOT)BAGCEPTION_CONT_Master_856bd140-6963-4de1-9471-25440149e87d, _Character, 1, 0);

// Everyone already in the party. Covers installing into an existing save, where
// CharacterJoinedParty has long since fired, and repairs any character who somehow
// has none. DB_Players binds once per party member, so the rule fires per character.
IF
SavegameLoaded()
AND
DB_Players(_Character)
AND
TemplateIsInInventory((ITEMROOT)BAGCEPTION_CONT_Master_856bd140-6963-4de1-9471-25440149e87d, _Character, 0)
AND
NOT DB_Bagception_GrantPending(_Character)
THEN
DB_Bagception_GrantPending(_Character);
TemplateAddTo((ITEMROOT)BAGCEPTION_CONT_Master_856bd140-6963-4de1-9471-25440149e87d, _Character, 1, 0);

IF
LevelGameplayStarted(_Level, 0)
AND
IsCharacterCreationLevel(_Level, 0)
AND
DB_Players(_Character)
AND
TemplateIsInInventory((ITEMROOT)BAGCEPTION_CONT_Master_856bd140-6963-4de1-9471-25440149e87d, _Character, 0)
AND
NOT DB_Bagception_GrantPending(_Character)
THEN
DB_Bagception_GrantPending(_Character);
TemplateAddTo((ITEMROOT)BAGCEPTION_CONT_Master_856bd140-6963-4de1-9471-25440149e87d, _Character, 1, 0);

// The bag has arrived, so the character is no longer pending. Clearing it here
// rather than never is what preserves self-healing: if the bag is later destroyed,
// a later sweep sees an empty inventory and no pending flag, and grants again.
IF
TemplateAddedTo((ITEMROOT)BAGCEPTION_CONT_Master_856bd140-6963-4de1-9471-25440149e87d, _Bag, _InventoryHolder, _AddType)
AND
IsCharacter(_InventoryHolder, 1)
THEN
NOT DB_Bagception_GrantPending(_InventoryHolder);

// The internal containers are NOT added here. They come from the master bag's
// InventoryList, which points at the BAGCEPTION_MasterContents treasure table, so
// the engine creates the bag already holding them.
//
// Adding them with Osiris worked, but left the client drawing an empty bag until
// the next reload: the container's UI is built when the bag arrives and is not
// refreshed when something is put into it a moment later. Declaring the contents on
// the template removes the second insertion entirely rather than trying to time it.


// ---------------------------------------------------------------------------
// SORTER
// ---------------------------------------------------------------------------
//
// These rules belong in their own goal, and Bagception_Sorter.txt holds the same
// text. They are duplicated here because the Story Editor compiles only goals it
// has registered, and a .txt dropped into RawFiles/Goals is not: the build reports
// 0 errors and silently omits it. Until the goal is created through the editor,
// this is the only registered goal the rules can live in.
//
// Route items dropped into a master bag to the container that should hold them.
//
// Per-item routing on TemplateAddedTo, chosen over bulk MagicPocketsMoveToByTag
// sweeps. Bulk can only match tags, so it cannot reach the six categories with no
// vanilla tag; its _Source is the party inventory pool, so it would pull items out of
// the character's own inventory and into Bagception, which is sorting outside our own
// hierarchy; and it needs an _Amount.
//
// The holder test is a tag check. The master bag's root template carries
// BAGCEPTION_MASTER, so IsTagged answers "is this a Bagception" directly, with no
// registry to populate and no repair path to get wrong. It is also what keeps the
// sorter inside our hierarchy: the holder must BE a master bag, never merely contain
// one, so a character's own inventory is never swept.
//
// GetItemByTemplateInInventory resolves a container template to the instance inside
// this particular bag, so the sub-container map is looked up rather than stored.
// ToInventory takes a GUIDSTRING target, so it moves into a container.
//
// Recursion takes care of itself: routing an item fires TemplateAddedTo again with
// the sub-container as holder, and sub-containers do not carry BAGCEPTION_MASTER.
//
// Amount -1 is the vanilla idiom for the whole stack. ShowNotification 0 keeps
// sorting silent. ClearOriginalOwner 0 preserves ownership, so filing a stolen item
// does not launder it.

// Potions. The first category, and the shape the other fifteen will copy.
IF
TemplateAddedTo(_Template, _Item, _InventoryHolder, _AddType)
AND
IsTagged(_InventoryHolder, (TAG)BAGCEPTION_MASTER_e9e54868-4241-49d7-b7ac-9202a8cd6397, 1)
AND
IsTagged(_Item, (TAG)ALCH_SOLUTION_POTION_8798a644-4720-4487-bc1a-6a4bf8f3a126, 1)
AND
GetItemByTemplateInInventory((ITEMROOT)BAGCEPTION_CONT_PotionCase_8bf1ed2d-3655-415e-868e-fe3138760337, _InventoryHolder, _PotionCase)
THEN
ToInventory(_Item, _PotionCase, -1, 0, 0);

// Scrolls. Tag-expressible, so the same shape as potions.
//
// This container shipped first with a ContainerContentFilterCondition and no rule, to
// test whether native auto-collect files items into a nested container. It does not:
// scrolls dropped into the master bag stayed loose. The filter still earns its place —
// it gates manual placement, refusing anything that is not a scroll — but the moving
// is ours to do. Every category needs a rule.
IF
TemplateAddedTo(_Template, _Item, _InventoryHolder, _AddType)
AND
IsTagged(_InventoryHolder, (TAG)BAGCEPTION_MASTER_e9e54868-4241-49d7-b7ac-9202a8cd6397, 1)
AND
IsTagged(_Item, (TAG)SCROLL_dd86c045-0370-4ec9-b7c5-b0b160706f09, 1)
AND
GetItemByTemplateInInventory((ITEMROOT)BAGCEPTION_CONT_ScrollCase_acf14532-8d31-4d94-b467-72018dd2cde9, _InventoryHolder, _ScrollCase)
THEN
ToInventory(_Item, _ScrollCase, -1, 0, 0);

// Alchemical ingredients.
//
// ALCH_INGREDIENT alone is enough, and extracts need no rule. A player never picks an
// extract up: reagents are the thing found in the world, and extracts are produced from
// them through the in-game extraction option, which deposits the result directly. So an
// extract does not arrive as a loose item that could be dragged into Bagception.
//
// This is why the six elemental ALCH_EXTRACT_* tags are not matched here, despite there
// being no plain ALCH_EXTRACT tag for them to share.
IF
TemplateAddedTo(_Template, _Item, _InventoryHolder, _AddType)
AND
IsTagged(_InventoryHolder, (TAG)BAGCEPTION_MASTER_e9e54868-4241-49d7-b7ac-9202a8cd6397, 1)

// Books and notes.
//
// The SCROLL exclusion is load-bearing. A scroll carries BOOK as well, so without it a
// scroll would match this rule and the Scroll Case rule both, and two rules would move
// the same item on the same event. Vanilla writes its own book container filter the
// same way: Tagged(BOOK) and not Tagged(SCROLL).
//
// This is the first place two categories overlap, and the pattern every later overlap
// follows: exclude explicitly rather than relying on rule order, which Osiris does not
// guarantee.
IF
TemplateAddedTo(_Template, _Item, _InventoryHolder, _AddType)
AND
IsTagged(_InventoryHolder, (TAG)BAGCEPTION_MASTER_e9e54868-4241-49d7-b7ac-9202a8cd6397, 1)
AND
IsTagged(_Item, (TAG)BOOK_8a8e253a-c081-45a1-9fa2-91b6901dc568, 1)

// Camp supplies.
//
// There is no supply tag. IsSupply() exists as a container filter predicate but not as
// an Osiris query, so the rule uses ItemGetSupplyValue instead: anything that feeds the
// camp has a supply value above zero. That covers food, drink and camp-supply packs
// alike, where the FOOD tag would miss the packs.
//
// This container is therefore filterable but not tag-routable -- the only one in the
// set where the filter and the rule use different mechanisms.
IF
TemplateAddedTo(_Template, _Item, _InventoryHolder, _AddType)
AND
IsTagged(_InventoryHolder, (TAG)BAGCEPTION_MASTER_e9e54868-4241-49d7-b7ac-9202a8cd6397, 1)
AND
ItemGetSupplyValue((ITEM)_Item, _SupplyValue)
AND
_SupplyValue > 0
AND
GetItemByTemplateInInventory((ITEMROOT)BAGCEPTION_CONT_LarderSack_5691a197-d3a9-46a3-be03-91cb09ec804e, _InventoryHolder, _DestLarderSack)
THEN
ToInventory(_Item, _DestLarderSack, -1, 0, 0);

// Shields. The first category with no vanilla tag, and the test of whether the
// classification strategy for the other five holds up.
//
// There is no Shield equipment slot: the EQUIPMENTSLOT enum runs Helmet, Breast,
// Cloak, MeleeMainHand, MeleeOffHand, RangedMainHand, RangedOffHand, Ring, Underwear,
// Boots, Gloves, Amulet, Ring2, Wings, Horns, Overhead, MusicalInstrument, VanityBody,
// VanityBoots, and shields share MeleeOffHand with off-hand weapons. The discriminator
// is therefore the slot AND not being a weapon.
//
// IsWeapon(_Item, 0) rather than NOT IsWeapon(...): NOT applies to database facts, not
// to queries, and a constant in an out-param position is the standard way to assert
// what a query returned. The EQUIPMENTSLOT constant is accepted the same way.
//
// Both queries need an explicit (ITEM) cast. TemplateAddedTo binds its second
// parameter as (GUIDSTRING)_Object, and GUIDSTRING does not narrow to ITEM by
// itself: the compiler reports a parameter type mismatch and skips the rule.
// IsTagged takes a GUIDSTRING, which is why the potion rule needs no cast and
// every rule reaching an ITEM-typed query does.
//
// A DYE tag resource exists but no root template carries it, so the same kind of
// reasoning will be needed for dyes. Weapons and jewelry are simpler, being a direct
// IsWeapon and a slot test respectively.
IF
TemplateAddedTo(_Template, _Item, _InventoryHolder, _AddType)
AND
IsTagged(_InventoryHolder, (TAG)BAGCEPTION_MASTER_e9e54868-4241-49d7-b7ac-9202a8cd6397, 1)
AND
GetEquipmentSlotForItem((ITEM)_Item, EQUIPMENTSLOT.MeleeOffHand)
AND
IsWeapon((ITEM)_Item, 0)
AND
GetItemByTemplateInInventory((ITEMROOT)BAGCEPTION_CONT_ShieldRack_feda4623-0e32-4d33-921a-fe62fdefde98, _InventoryHolder, _ShieldRack)
THEN
ToInventory(_Item, _ShieldRack, -1, 0, 0);
