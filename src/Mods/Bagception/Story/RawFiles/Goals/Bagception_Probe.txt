INITSECTION

// Bagception.
//
// Grants one Bagception per character with its internal containers, keeps existing
// bags up to date, and sorts what is put into a Bagception into the right container.
// The goal keeps its Phase 1 name, Bagception_Probe: saves record goals by name, so
// renaming it would start a second goal in every save that has the first.
//
// DB_Bagception_GrantPending is declared here only to give the database a defined
// shape; the NULL entry never matches a real character.
//
// GUIDSTRING, not CHARACTER. The grant rules bind a CHARACTER, but the rule that
// clears the flag takes its holder from TemplateAddedTo, whose _InventoryHolder is a
// GUIDSTRING. GUIDSTRING accepts a CHARACTER; the reverse is a type error.
DB_Bagception_GrantPending((GUIDSTRING)NULL_00000000-0000-0000-0000-000000000000);

// The init section no longer carries the grant flag. The grant used to hang off a DB flag asserted
// here, which was consumed once and could never recover if the grant was missed.
// The inventory-count guard below replaces it and is self-healing.

// Sorting data -- the book, slot, tool and container lists -- is not asserted here.
// The init section runs once, when the goal first starts in a save, so a later version of
// the mod could never add to a list in a save that already has it. The data lives in
// PROC_Bagception_LoadData below instead, reloaded on every load.

KBSECTION

// ---------------------------------------------------------------------------
// SHIPPING: one Bagception per character
// ---------------------------------------------------------------------------
//
// Follows the vanilla pattern for the camp supply pack in Gustav's _Gustav_Init:
// react to CharacterJoinedParty, and guard with TemplateIsInInventory(..., 0) so a
// character who already has one is skipped. Vanilla adds QRY_OnlyOnce because the
// pack is one per party; Bagception is one per character, so that guard is dropped
// and the inventory check does the work instead.
//
// The inventory check is what makes these rules idempotent and self-healing: they
// can fire as often as they like and a character ends up with exactly one bag. That
// is a better guard than the DB flag used earlier, which was consumed once and
// could never recover if the grant was missed.

// New arrivals: recruits, hirelings, anyone joining later.
IF
CharacterJoinedParty(_Character)
AND
TemplateIsInInventory((ITEMROOT)BAGCEPTION_CONT_Master_856bd140-6963-4de1-9471-25440149e87d, _Character, 0)
AND
NOT DB_Bagception_GrantPending(_Character)
THEN
DB_Bagception_GrantPending(_Character);
TemplateAddTo((ITEMROOT)BAGCEPTION_CONT_Master_856bd140-6963-4de1-9471-25440149e87d, _Character, 1, 0);

// Everyone already in the party. Covers installing into an existing save, where
// CharacterJoinedParty has long since fired, and repairs any character who somehow
// has none. DB_Players binds once per party member, so the rule fires per character.
IF
SavegameLoaded()
AND
DB_Players(_Character)
AND
TemplateIsInInventory((ITEMROOT)BAGCEPTION_CONT_Master_856bd140-6963-4de1-9471-25440149e87d, _Character, 0)
AND
NOT DB_Bagception_GrantPending(_Character)
THEN
DB_Bagception_GrantPending(_Character);
TemplateAddTo((ITEMROOT)BAGCEPTION_CONT_Master_856bd140-6963-4de1-9471-25440149e87d, _Character, 1, 0);

IF
LevelGameplayStarted(_Level, 0)
AND
IsCharacterCreationLevel(_Level, 0)
AND
DB_Players(_Character)
AND
TemplateIsInInventory((ITEMROOT)BAGCEPTION_CONT_Master_856bd140-6963-4de1-9471-25440149e87d, _Character, 0)
AND
NOT DB_Bagception_GrantPending(_Character)
THEN
DB_Bagception_GrantPending(_Character);
TemplateAddTo((ITEMROOT)BAGCEPTION_CONT_Master_856bd140-6963-4de1-9471-25440149e87d, _Character, 1, 0);

// The bag has arrived, so the character is no longer pending. Clearing it here
// rather than never is what preserves self-healing: if the bag is later destroyed,
// a later sweep sees an empty inventory and no pending flag, and grants again.
IF
TemplateAddedTo((ITEMROOT)BAGCEPTION_CONT_Master_856bd140-6963-4de1-9471-25440149e87d, _Bag, _InventoryHolder, _AddType)
AND
IsCharacter(_InventoryHolder, 1)
THEN
NOT DB_Bagception_GrantPending(_InventoryHolder);

// The internal containers are NOT added here. They come from the master bag's
// InventoryList, which points at the BAGCEPTION_MasterContents treasure table, so
// the engine creates the bag already holding them.
//
// Adding them with Osiris worked, but left the client drawing an empty bag until
// the next reload: the container's UI is built when the bag arrives and is not
// refreshed when something is put into it a moment later. Declaring the contents on
// the template removes the second insertion entirely rather than trying to time it.

// ---------------------------------------------------------------------------
// SHIPPING: sorting data, and keeping existing bags up to date
// ---------------------------------------------------------------------------
//
// Everything the sorter looks up -- templates, slots, stats names, the container list --
// is asserted here rather than in the init section, which runs only once per save. Reloading
// on SavegameLoaded is what lets an update reach a save already in progress: a list that
// grows in a later version grows in the save on its next load.
//
// The clear comes first so the reload is exact rather than additive: an entry a later
// version drops is dropped from the save too. It also clears the copies earlier versions
// asserted from the init section. Clear and reload run inside one PROC call, so no sorting
// rule can run between them.
//
// LevelGameplayStarted covers a new game, where no save is loaded, and every level change
// after it. Reloading more often than needed costs nothing.
IF
SavegameLoaded()
THEN
PROC_Bagception_LoadData();
PROC_Bagception_RepairParty();

IF
LevelGameplayStarted(_Level, _IsEditorMode)
THEN
PROC_Bagception_LoadData();

// Repair: give an existing Bagception any internal container it lacks.
//
// A bag gets its containers from the treasure table once, when it is created, so a bag
// from an earlier version never receives a container added since. This adds each
// missing one, and is what makes a new container reach a save already in progress.
//
// It must never run while a bag is still being filled. A new bag's contents arrive in
// events of their own after the bag itself, so a check in between would see an empty
// bag and add a second copy of everything. Both triggers are clear of that window.
// SavegameLoaded sees only bags that were saved whole; one granted by the grant rule on
// the same event is still in flight, so GetItemByTemplateInInventory finds nothing.
// CharacterJoinedParty fires before a newcomer's bag is granted, so it repairs only a
// character who already had one: a companion rejoining from camp, who may have been
// out of the party when the save loaded.
//
// The known cost is cosmetic: a container added to a bag that already exists may not
// be drawn until the next reload, as with the earlier Osiris-added containers.
PROC
PROC_Bagception_RepairParty()
AND
DB_Players(_Character)
AND
GetItemByTemplateInInventory((ITEMROOT)BAGCEPTION_CONT_Master_856bd140-6963-4de1-9471-25440149e87d, _Character, _Bag)
THEN
PROC_Bagception_RepairBag(_Bag);

IF
CharacterJoinedParty(_Character)
AND
GetItemByTemplateInInventory((ITEMROOT)BAGCEPTION_CONT_Master_856bd140-6963-4de1-9471-25440149e87d, _Character, _Bag)
THEN
PROC_Bagception_RepairBag(_Bag);

// ---------------------------------------------------------------------------
// SORTER
// ---------------------------------------------------------------------------
//
// These rules belong in their own goal, and Bagception_Sorter.txt holds the same
// text. They are duplicated here because the Story Editor compiles only goals it
// has registered, and a .txt dropped into RawFiles/Goals is not: the build reports
// 0 errors and silently omits it. Until the goal is created through the editor,
// this is the only registered goal the rules can live in.
//
// Route items dropped into a master bag to the container that should hold them.
//
// Per-item routing on TemplateAddedTo, chosen over bulk MagicPocketsMoveToByTag
// sweeps. Bulk can only match tags, so it cannot reach the six categories with no
// vanilla tag; its _Source is the party inventory pool, so it would pull items out of
// the character's own inventory and into Bagception, which is sorting outside our own
// hierarchy; and it needs an _Amount.
//
// The holder test is a tag check. The master bag's root template carries
// BAGCEPTION_MASTER, so IsTagged answers "is this a Bagception" directly, with no
// registry to populate and no repair path to get wrong. It is also what keeps the
// sorter inside our hierarchy: the holder must BE a master bag, never merely contain
// one, so a character's own inventory is never swept.
//
// GetItemByTemplateInInventory resolves a container template to the instance inside
// this particular bag, so the sub-container map is looked up rather than stored.
// ToInventory takes a GUIDSTRING target, so it moves into a container.
//
// Recursion takes care of itself: routing an item fires TemplateAddedTo again with
// the sub-container as holder, and sub-containers do not carry BAGCEPTION_MASTER.
//
// Amount -1 is the vanilla idiom for the whole stack. ShowNotification 0 keeps
// sorting silent. ClearOriginalOwner 0 preserves ownership, so filing a stolen item
// does not launder it.

// Story items. They go to the Quest Satchel ahead of every category, so the Moonlantern
// is a quest item before it is a light, and every category rule below carries
// IsStoryItem 0 to stay out of its way. Two exceptions:
// - keys. Every vanilla key is a story item, inherited from BASE_KEY, so this rule
//   would empty the Key Ring. Keys stay there, story or not.
// - containers, which stay at the top level whatever they are (spec section 6.19).
// Items collected on pickup by the Reagent Pouch, Larder Pack and Coin Purse bypass
// the sorter, and their filters cannot test for story items.
IF
TemplateAddedTo(_Template, _Item, _InventoryHolder, _AddType)
AND
IsTagged(_InventoryHolder, (TAG)BAGCEPTION_MASTER_e9e54868-4241-49d7-b7ac-9202a8cd6397, 1)
AND
IsStoryItem((ITEM)_Item, 1)
AND
IsTagged(_Item, (TAG)KEY_9851fa99-5538-432a-8e77-c90929a88974, 0)
AND
IsContainer((ITEM)_Item, 0)
AND
GetItemByTemplateInInventory((ITEMROOT)BAGCEPTION_CONT_QuestSatchel_651a1742-b423-4fc5-8990-52d2e61f746e, _InventoryHolder, _DestQuestSatchel)
THEN
ToInventory(_Item, _DestQuestSatchel, -1, 0, 0);

// Shields. The first category with no vanilla tag, and the test of whether the
// classification strategy for the other five holds up.
//
// There is no Shield equipment slot: the EQUIPMENTSLOT enum runs Helmet, Breast,
// Cloak, MeleeMainHand, MeleeOffHand, RangedMainHand, RangedOffHand, Ring, Underwear,
// Boots, Gloves, Amulet, Ring2, Wings, Horns, Overhead, MusicalInstrument, VanityBody,
// VanityBoots, and shields share MeleeOffHand with off-hand weapons. The discriminator
// is therefore the slot AND not being a weapon.
//
// IsWeapon(_Item, 0) rather than NOT IsWeapon(...): NOT applies to database facts, not
// to queries, and a constant in an out-param position is the standard way to assert
// what a query returned. The EQUIPMENTSLOT constant is accepted the same way.
//
// Both queries need an explicit (ITEM) cast. TemplateAddedTo binds its second
// parameter as (GUIDSTRING)_Object, and GUIDSTRING does not narrow to ITEM by
// itself: the compiler reports a parameter type mismatch and skips the rule.
// IsTagged takes a GUIDSTRING, which is why the potion rule needs no cast and
// every rule reaching an ITEM-typed query does.
IF
TemplateAddedTo(_Template, _Item, _InventoryHolder, _AddType)
AND
IsTagged(_InventoryHolder, (TAG)BAGCEPTION_MASTER_e9e54868-4241-49d7-b7ac-9202a8cd6397, 1)
AND
IsStoryItem((ITEM)_Item, 0)
AND
GetEquipmentSlotForItem((ITEM)_Item, EQUIPMENTSLOT.MeleeOffHand)
AND
IsWeapon((ITEM)_Item, 0)
AND
GetItemByTemplateInInventory((ITEMROOT)BAGCEPTION_CONT_ShieldRack_feda4623-0e32-4d33-921a-fe62fdefde98, _InventoryHolder, _ShieldRack)
THEN
ToInventory(_Item, _ShieldRack, -1, 0, 0);

// Miscellaneous: whatever no other rule claimed goes to the Odds Sack.
//
// A catch-all cannot be one more TemplateAddedTo rule. Osiris does not promise rule
// order, so it would race every category rule for the same item, and writing it as
// "none of the above" means repeating every other rule's conditions, negated, and
// keeping them in step forever. It waits instead. Every arrival in the master bag starts
// a short timer on the item; when it runs out, anything still lying directly in the
// master bag is by definition something nothing else took. The category rules are never
// named here, so a container added later needs no change to this one.
//
// The internal containers themselves arrive in the master bag too, when it is created;
// they are skipped before a timer starts rather than after.
IF
TemplateAddedTo(_Template, _Item, _InventoryHolder, _AddType)
AND
IsTagged(_InventoryHolder, (TAG)BAGCEPTION_MASTER_e9e54868-4241-49d7-b7ac-9202a8cd6397, 1)
AND
IsTagged(_Item, (TAG)BAGCEPTION_INTERNAL_a97f9268-5575-4f3d-8bca-58b31986b308, 0)
THEN
RealtimeObjectTimerLaunch(_Item, "Bagception_Leftover", 1000);

// Realtime rather than ObjectTimerLaunch, which ticks by turn during combat.
//
// What stays at the top level on purpose, per spec sections 6.18, 6.19 and 7:
// - any container, from vanilla or another mod, so Bagception never sorts into or
//   dismantles someone else's organisation;
// - story items, which have the Quest Satchel. They are still excluded here, so that
//   in a bag missing its satchel they stay loose rather than going to the Odds Sack;
// - gold, which has the Coin Purse. It is still excluded here, so that in a bag
//   missing its purse gold stays loose rather than going to the Odds Sack.
//
// GetDirectInventoryOwner is the check that the item is still where it arrived. Filed,
// dragged out, or dropped in the meantime, it answers something else and nothing moves.
IF
ObjectTimerFinished(_Item, "Bagception_Leftover")
AND
GetDirectInventoryOwner(_Item, _Holder)
AND
IsTagged(_Holder, (TAG)BAGCEPTION_MASTER_e9e54868-4241-49d7-b7ac-9202a8cd6397, 1)
AND
IsContainer((ITEM)_Item, 0)
AND
IsStoryItem((ITEM)_Item, 0)
AND
IsTagged(_Item, (TAG)LOOT_GOLD_6c6b7cac-113c-42ee-bc46-05567b067a9f, 0)
AND
GetStatString(_Item, _Stat)
AND
_Stat != "OBJ_GoldCoin"
AND
_Stat != "OBJ_GoldPile"
AND
GetItemByTemplateInInventory((ITEMROOT)BAGCEPTION_CONT_OddsSack_d50b2909-3daa-439b-aeb0-11e97a369521, _Holder, _DestOddsSack)
THEN
ToInventory(_Item, _DestOddsSack, -1, 0, 0);
